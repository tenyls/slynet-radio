# SlyNet Radio · 2G

Дополнительная лёгкая мобильная оболочка: **https://2g.slynet-radio.pages.dev/**.
Основные адреса, исходники `src/`, APK, OTA и `worker/index.js` не меняются.

## Данные и функции

- `lite/App.tsx` — простое меню и текстовые списки по 20 станций; поиск выполняется по кнопке, без запросов на каждую букву.
- Плеер, аккаунт, синхронизация, избранное, плейлисты, история/треки, шаринг/QR, таймер, будильник, запись,
  режим «За рулём», поддержка и админка используют существующий код `src/`. Ограничения браузера остаются прежними.
- Все разделы доступны из меню, включая артистов, настроение, приложения, оформление, ТВ и камеры.
  География радио представлена статичной картой и выбором города вместо вращающегося WebGL-глобуса.
- Режим «Слабый интернет» включён при первом посещении, его можно переключить. Лёгкий поток выбирается **только если он существует** у вещателя.
  Оболочка не пережимает эфир. Для станций без лёгкого варианта хорошее воспроизведение в 2G не гарантируется.
- Системный шрифт, без анимаций, `requestAnimationFrame`-визуализатора и скачивания шрифтов. Изображения выключены по умолчанию,
  включаются в «Главная → Экономия трафика». HLS, полный каталог и дополнительные экраны загружаются при использовании.
  Перед загрузкой ТВ/камер есть отдельная кнопка; автообновление кадров камеры изначально выключено.
- Аккаунт тот же. На новом адресе браузер хранит локальные данные отдельно: нужно снова войти или перенести избранное
  через «Войти / перенести избранное» (ссылка/файл). Существующие аккаунты и данные серверного KV не переносятся и не меняются.
- Видимость разделов/стран, запреты станций и разрешения владельца берутся из общих настроек и применяются как на основном сайте.
- Ссылки «Поделиться» и рекламные ссылки сохраняют основной адрес по договорённости владельца.

## Как обновляется

1. `.github/workflows/deploy-lite.yml` запускается при push в `main`, вручную и после успешного workflow «Обновить каталог».
   Последний триггер нужен потому, что push от `GITHUB_TOKEN` бота не запускает обычный push-workflow.
2. `node lite/build.mjs` собирает отдельный `dist-lite/`. `core.json` — компактная производная **того же** `public/catalog.json`:
   все эксклюзивы, подборки, альтернативные потоки и список неработающих станций; без каталога артистов/ТВ на старте.
3. `lite/vite.config.ts` применяет адаптеры **только внутри 2G-сборки**. Не переносить их в основной `vite.config.ts`.
4. Wrangler публикует `dist-lite` в существующий Pages-проект `slynet-radio`, **только с `--branch 2g`**.
   Это постоянный branch alias, не отдельная ветка Git и не замена production `main`.
5. Контент, полный каталог, география и метаданные версий читаются с **основного** сайта через фиксированные `/data/*` маршруты.
   `content.json` — без кэша HTTP, остальная публичная информация — до 5 минут.

## Сервер лёгкой оболочки

`lite/worker.js` → `dist-lite/_worker.js` — Pages Function **только в 2G-развёртывании**.
Основной `slynet-api` менять/выкладывать вручную не нужно. Новых секретов и KV-привязок нет.

- `/api/*` передаёт только перечисленные в `API_PATH` маршруты существующего `slynet-api`. Он продолжает проверять пароли/токены.
  Запросы уходят с разрешённым Origin основного сайта, поэтому старый CORS не нужно менять.
- Авторизация передаётся в `Authorization`; cookies и произвольные адреса не проксируются. Ответы API — `no-store`.
  Сторонний Origin блокируется. `/geo` использует страну посетителя на стороне Pages.
- `lite/api.ts` меняет только **транспорт** API. В `settings.apiUrl` остаётся канонический адрес, чтобы публикация из админки
  случайно не записала `/api` в общий `content.json` и не сломала основные сайты.
- `_routes.json` отправляет в Functions только динамические маршруты. Статические файлы оболочки обслуживает Pages.
- `lite/sw.js` кэширует оболочку и публичные данные для повторного открытия. API аккаунтов, токены и радиопотоки не кэшируются.
  Радио для воспроизведения требует сети. При отсутствии сети опубликованные настройки могут быть взяты из последней успешной загрузки.

## Сборка и проверки

```text
npm ci
npm run build
node --test lite/worker.test.mjs
node lite/build.mjs
node lite/check-build.mjs
```

`check-build.mjs` проверяет граф стартовой загрузки: нет HLS/WebGL/админки/камер/шрифтов на старте,
нет предварительной загрузки HLS, используется компактный каталог. Бюджет старта — 180 000 байт gzip,
включая HTML/CSS/JS и `core.json`, без радиопотока и загружаемого `content.json` (~3 КБ без сжатия).
Итоговая метрика записывается в `dist-lite/performance.json`. Это размер файлов, а не измерение мобильной сети.

Локальный production-preview: `node lite/preview.mjs` → http://127.0.0.1:3001.
После пересборки перезагрузить вкладку: старые ссылки на динамические файлы уже не существуют в локальном `dist-lite`.

Перед выпуском проверить: мобильное меню, запуск/паузу, избранное после перезагрузки, свои плейлисты,
шаринг/QR, окно аккаунта, общие настройки/каталог, географию, явную загрузку ТВ/камер, отсутствие анимаций и запросов картинок по умолчанию.
Вход с личными данными и качество на реальном слабом соединении подтверждает владелец.

Откат: GitHub → Actions → «Публикация лёгкой версии 2G» → предыдущий рабочий код/повтор сборки.
Не запускать публикацию `dist-lite` с `--branch main`; не менять основную production-ветку Pages.
